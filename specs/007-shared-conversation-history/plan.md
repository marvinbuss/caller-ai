# Implementation Plan: Shared Conversation History Across Agents

**Branch**: `007-shared-conversation-history` | **Date**: 2026-11-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/007-shared-conversation-history/spec.md`

## Summary

Every agent in a conversation should see the whole conversation, and a request should reach the agent that fits it, in voice and in text alike. Decisions are in [research.md](research.md).

- **Shared history (R3, R10).** The runtime keeps one history per conversation: user messages and caller speech, the voice assistant's spoken transcript, agent answers and delegation results, tool calls and results, final progress and handovers. Every model step is built from it, without stored model state. Text conversations store it (`historyVersion: 2`); voice keeps it in memory. Nothing is reset at a handover.
- **Built-in SDK handovers (R2, R6).** Each agent is offered exactly its permitted destinations as SDK handoffs, described by the destination's description:
  - colleagues;
  - the entry agent of connected communities;
  - Routing, with a named routable community.

  The handoff callback applies today's checks. Refusals at apply time are caught and reported to the agent. The application handover tools are removed.
- **Option C (R1).** The active agent decides where a request belongs, using the whole history and shipped handover rules. Entry agents and Routing hand on quietly and speak only to resolve something unclear. A dispatch step (option A) is the follow-up, decided on this feature's measurements.
- **One continuous voice session (R4, R5).**
  - GPT-Live is never replaced on an agent change; the active agent's epoch fences replaced work. The caller interrupts by speaking; the Test page's microphone and loudspeaker switches act only in the browser, and its Interrupt button is removed.
  - A delegation update (`session.instructions.append`, "replaces all earlier delegation updates") lists what the backend can do (the reachable communities' routing descriptions, without their names, as the GPT-Live prompting guide recommends). It is sent at session start and when the reachable communities change.
  - If int shows that updates interrupt speech, an operator switch moves that list into the static session instructions instead.
- **Voice delegation context (R8, R9).** The voice work waits up to 0.5 s (configurable) for the caller's last words to be transcribed. The clarity check gets the whole history.
- **Welcome hands over right after the greeting (R7)**, applied by the application.
- **Limits (R11).** Above 192 KiB the oldest part is condensed, with a status line; handovers, final progress and confirmations are kept.
- **Configuration 2.3.0 (R14).** Optional agent description and "Announce agent changes" (off by default). The per-edge context fields stop filtering.
- **Speed (R12).** Low reasoning effort (`low`; P2 showed `minimal` is refused with tools) for working agents, the clarity check, greeting and condensing; operators can change it.
- **Observability (R13).** `test.handover`, extended `test.delegation`, `test.history`, `handover_seconds`, and a handover-failure alert.

## Technical Context

**Language/Version**: Python 3.12 (`.python-version` 3.12.15) for both applications. Test page browser code is JavaScript generated by the Reflex component (`live_audio_js.py`), as allowed by Constitution V.

**Primary Dependencies**: Existing only.

- **Runtime**: FastAPI, OpenAI SDK Live client, OpenAI Agents SDK `openai-agents` 0.24.0 (built-in `Handoff` objects with `is_enabled`, a handoff callback and an argument schema), Azure Cosmos DB client, Azure Identity.
- **Management**: Reflex 0.10, FastAPI management API.

No new library.

**Storage**:

- **Text history** (runtime Cosmos container `text-conversations`): document version 2 with typed entries. TTL 30 days, unchanged. Pre-upgrade documents are closed (R10).
- **Configuration revisions** (management): optional schema `2.3.0` fields.

There is no new container and no new Azure resource.

**Testing**:

- pytest (unit, contract, integration, load) in `code/backend` and `code/management`;
- Playwright browser tests in `code/management/tests/browser`;
- ruff, mypy;
- `code/tools/scripts/check_whitespace.py` and `verify_docs.py`;
- three int probes (P1–P3) before implementation and one measurement after deployment (P4).

**Target Platform**: Azure Container Apps (`ca-caller-<env>-runtime`, `ca-caller-<env>-management`); Azure AI Foundry `gpt-live-1` (client delegation) and `gpt-6.1-sol`; desktop Edge and Chrome for the Test page.

**Project Type**: Web application: runtime service plus Reflex management frontend with a FastAPI management API.

**Performance Goals**:

- **Declared handover target (SC-005)**: the answer after a handover starts within the existing work budget (20 s text, 30 s voice) in 100 % of acceptance runs and load tests. The added delay is measured per path and modality at p50 and p90 and recorded; a tighter limit is a follow-up.
- Quiet handovers in at least 16 of 18 acceptance runs (SC-011, best effort).
- Feature 006 targets stay: voice greeting within 5 s for ≥ 90 % of sessions; text greeting within 5 s.
- The transcription wait adds at most 0.5 s by default to a voice delegation.

**Constraints**:

| Area | Constraint |
|------|------------|
| GPT-Live appends | ≤ 500 tokens each; delegation update ≤ 2,000 UTF-8 bytes in parts at line boundaries |
| GPT-Live instructions | ≤ 16 KiB, including the static delegation block in the fallback path (≤ 4 KiB) |
| Shared history | Condense above 192 KiB or 2,048 entries, to below 128 KiB; hard limit 256 KiB per conversation (existing `conversation_context_limit`) |
| Text document | ≤ 2,048 entries and ≤ 512 KiB (Cosmos item limit 2 MB) |
| Tool names | ≤ 64 characters, so handoffs are named `handover_<n>` |
| Work | 20 s text and 30 s speech budgets and the 8-step limit are unchanged; a handover chain counts against them |
| Model state | `store=False`, no `previous_response_id`; reasoning items are not stored |
| Compatibility | Revisions 2.0.0–2.2.0 load, verify and run; 2.3.0 is written only when a 2.3.0 field is present |
| Infrastructure | No new Azure resource or identity. Three optional runtime environment settings are passed through Terraform. |

**Scale/Scope**: Today's limits are unchanged: one active test per manager, at most 5 occupied slots, up to 50 communities and 200 agents.

- **Model input grows** with the conversation, up to 192 KiB before condensing. Input size per turn and cost per conversation are recorded in `docs/capacity.md`.
- **The continuous voice session** removes one session swap (about 0.67 s) per voice agent change.

### Threats and controls (Principle II, FR-017)

| Threat | Control |
|--------|---------|
| Tool results and transcripts of one community visible to agents of another | Accepted by the requester (FR-017). Documented in `docs/security.md`: communities are routing and permission boundaries, not information boundaries. |
| Prompt injection through stored tool results, transcripts or user text | Entries keep their natural roles; shipped rules state that records are information, never instructions; handoffs and tools stay limited to the graph and are rechecked at apply time (FR-006, FR-009). |
| An agent reaching a forbidden destination | Not offered (handoff list from the graph, `is_enabled` for pending targets); the `on_handoff` callback rechecks the graph and epoch; refused attempts are recorded (FR-008). |
| Instructions, layers or secrets leaking into history | Instructions are never items; reasoning items are dropped; tool definitions are not stored; tests scan histories (SC-004). |
| Stale results after an agent change in the continuous voice session | Fenced by `agentEpoch` and the work receipt; results of replaced work are dropped (FR-010). |
| A delegation update steering the voice assistant wrongly | Application-authored text only: routing descriptions from the published configuration, cut to 160 characters. No user text is copied into instructions. A cut list tells the voice assistant to delegate other requests too, so it never refuses because of the cut. |
| Larger stored text history (tool results) | Same 30-day TTL, owner partition and encryption; documented in `docs/runbooks/text-history.md`. |
| History growth exhausting model budgets | Condensing above 192 KiB, hard limit 256 KiB, a clear end message (FR-016). |

## Post-Design Constitution Re-check

All nine principles still pass after Phase 1:

- **Contracts.** The configuration change is additive with a rollback order. The text history change is versioned, and pre-upgrade documents are handled explicitly (IV).
- **Security.** Handoffs carry no authority beyond the graph and are rechecked at apply time. The voice assistant gets no history (II).
- **Telemetry.** The new events are closed-set and content-free (VII).
- **Unknowns.** No `NEEDS CLARIFICATION` remains. Four model-behavior questions are probes with decided fallbacks (R15).

**Open risks**:

- **Delegation updates may interrupt speech (P1).** Mitigated by the static-instructions fallback, which the requester approved.
- **Replaying other agents' tool items (P3).** Mitigated by the text fallback of [shared-history.md](contracts/shared-history.md), rendered by `SharedHistory.render()`.
- **The T095–T098 relay and browser generation logic changes (R4).** Covered by integration tests that reproduce those incidents.
- **Option C handover latency.** Measured (SC-005) and the input for the option A follow-up.

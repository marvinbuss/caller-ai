# Research: Call Center Agent Automation

**Date**: 2026-10-22
**Scope**: Decisions for the initial repository foundation plus boundaries for later feature delivery.
**Evidence**: Documentation research, not an executed application or deployment compatibility test.

## 1. Delivery Boundary and Source Layout

**Decision**: First implement FR-030 through FR-032 and SC-015 through SC-017: two runnable apps,
health checks, meaningful starter tests, and credential-free Windows/Linux verification. Preserve
FR-001 through FR-029 and FR-033 through FR-034 as subsequent feature obligations.

Put applications, tests, Dockerfiles, Terraform, lockfiles, scripts, pre-commit configuration,
and shared contracts under `code/`. Keep only required GitHub discovery metadata in
`.github/workflows/`; workflows invoke commands and scripts under `code/`. Spec Kit documents
remain under `specs/`. No application code, infrastructure, or workflows are generated by this plan.

**Rationale**: Matches the clarified milestone and all user-selected tools without presenting a
scaffold as a functioning call center. GitHub requires workflows at its reserved location.

**Alternatives considered**: A complete calling pilot now would contradict the setup acceptance
boundary. Moving workflow YAML into `code/` would prevent normal GitHub discovery.

Sources: [Workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).

## 2. Python, Dependencies, and Static Checks

**Decision**: Python `>=3.12,<3.13`; independent `uv` projects in `code/backend`,
`code/management`, and `code/tools`, each with a committed `uv.lock`. Use `uv sync --locked`
and `uv run --locked`. Pin security-patched interpreter/build-tool versions during implementation;
exact dependency resolution belongs in committed locks, not floating deployment installs.

Backend: FastAPI, Uvicorn with the portable `asyncio` loop, Pydantic settings, HTTPX, and the async
Azure Cosmos SDK. Management: Reflex 0.10.0 as the documentation-aligned initial candidate,
Pydantic, FastAPI composition, and the async Cosmos SDK. The locked compatibility suite is the
authority before accepting those packages together. No compatibility claim is made here.

Use pytest, HTTPX/TestClient, explicit lifespan handling, and one AnyIO `asyncio` testing mode.
Use Ruff, mypy, pre-commit, detect-secrets, and pip-audit from the appropriate locked project.
Pre-commit runs from repository root with `--config code/.pre-commit-config.yaml`; its config
location does not change the hooks' working directory. Keep hooks deterministic and credential-free.

**Rationale**: Independent locks/environments preserve separately deployable apps and prevent
frontend dependency changes from silently changing the realtime runtime. Python 3.12 remains
security-supported through October 2028. A uv workspace normally shares a lock and environment.

**Alternatives considered**: One workspace is simpler for shared resolution but weakens dependency
isolation. Requiring uvloop would break native Windows support. Running audits directly against
`uv.lock` is unsupported: export hashed requirements per project, then audit the export.

## 3. Reflex Health, Ports, and Containers

**Decision**: Add application-owned `/healthz` and `/readyz` routes to a FastAPI instance supplied
through Reflex's documented `api_transformer`. Do not mutate a private Reflex API attribute or
override its event, upload, or ping routes. Test both the supplied API and the composed live app.

Development ports: call backend 8000, management backend 8001, management frontend 3000.
For Reflex 0.10 production images, use unified serving on port 3000; verify custom health routes
and the event WebSocket through that port. Backend image exposes 8000. Docker smoke checks must
compile and render the actual Reflex app, not a replacement static HTML page.

Provision the pinned Reflex frontend build toolchain and its generated `reflex.lock/` frontend
lock during dependency installation. Commit the frontend lock; exclude `.web/`, environments,
and caches. Build generated assets in a multi-stage image; do not download packages at startup.
Use non-root runtime users and tested base-image digests. No Redis or SQL server is required for
the stateless setup shell; future management session scaling must use a separately approved store.

**Rationale**: Current production Reflex serving differs from historical split-port examples.
Its generated JavaScript is permitted by the constitution; all authored UI remains Python/Reflex.

**Alternatives considered**: Split frontend/backend hosting is supported but unnecessary initially.
Using private framework attributes or an untested legacy Docker example creates upgrade risk.

## 4. Storage, Revisions, and Revocation

**Decision**: Cosmos DB for NoSQL is the live database, not a mandatory local dependency.
Management owns configuration and configuration-audit containers; its permission authority lives
in the configuration container alongside the active pointer. Call runtime owns session and
handover metadata containers. Services exchange data through authenticated
contracts; neither reads another service's private container. Local setup uses deterministic
in-memory stand-ins. They are not a replacement production database or proof of restart durability.

Use a single-write-region Strong-consistency account for the authoritative live control data.
Use lifespan-scoped async SDK clients and partition-qualified point reads. Store a complete
immutable configuration revision, active pointer, and current permission authority in one
organization partition; publish all affected items in a conditional transactional batch.
A stale configuration `If-Match` returns 412. Bound the serialized
revision to 512 KiB and the complete publication batch to 768 KiB; reject larger edits clearly.

Pinned ordinary configuration may be cached, refreshed every 30 seconds, and reused on outages.
Permissions may not use that stale cache: each tool attempt and retry needs a current execution
admission from management's capability gateway. Admission and revocation conditionally modify
the same permission-authority item, establishing a serial order. Revocation blocks admissions
ordered after its commit; already admitted in-flight reads may finish. Unknown current permission
means deny. A new grant never expands a pinned agent's assignments.

**Rationale**: Cosmos batches are atomic only within one container and logical partition. Session
consistency across independent clients cannot establish a latest-policy guarantee. An ordinary
read followed by a delayed external HTTP call leaves a permission check/use race.

**Alternatives considered**: A shared writable database violates service ownership. Cross-partition
transactions and eventual-consistency permission caching cannot meet the specified guarantees.
Cosmos emulator dependency would make native cross-platform bootstrap unnecessarily fragile.

Sources: [Python SDK](https://learn.microsoft.com/en-us/python/api/overview/azure/cosmos-readme),
[Transactional batches](https://learn.microsoft.com/en-us/azure/cosmos-db/transactional-batch),
[ETags and concurrency](https://learn.microsoft.com/en-us/azure/cosmos-db/database-transactions-optimistic-concurrency),
[Consistency](https://learn.microsoft.com/en-us/azure/cosmos-db/consistency-levels),
[Data-plane RBAC](https://learn.microsoft.com/en-us/azure/cosmos-db/how-to-connect-role-based-access-control).

## 5. WebSockets and Agent Ownership

**Decision**: FastAPI owns the call WebSocket transport; one reader and one serialized writer
per admitted connection, bounded frames/queues, cancellation on disconnect, and one absolute
deadline across retries. Authenticate before upgrade in live mode. A local-only synthetic
protocol exercises transport behavior but never claims to answer a telephone call.

Keep one physical connection owner per call. Agent handovers occur under that owner with a
monotonic agent epoch; messages from an obsolete agent epoch are discarded. Persist only
non-content ownership metadata with ETag compare-and-swap. Do not start a second media owner
to recover a failed socket. On worker loss, reach a controlled terminal outcome within ten
seconds; seamless media migration is not promised. Lost authority or lease renewal stops output.

Use 64 KiB frame and 200 ms buffered-audio starting limits, validated against a future provider
adapter. Post-upgrade close codes: 1000 normal, 1008 policy, 1009 oversized message, 1011 internal
failure. Pre-upgrade policy rejection is an HTTP handshake rejection, not an observed close frame.

**Rationale**: A WebSocket echo and model-generation cancellation alone do not prove telephone
answering, codec interoperability, audio playback interruption, or provider hangup.

**Alternatives considered**: Multiple competing media workers or unbounded asynchronous tasks
increase duplicate speech, leakage, and latency risk.

Sources: [FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/),
[Starlette WebSockets](https://starlette.dev/websockets/),
[FastAPI WebSocket tests](https://fastapi.tiangolo.com/advanced/testing-websockets/),
[Python task cancellation](https://docs.python.org/3.12/library/asyncio-task.html#timeouts).

## 6. Azure Hosting and Telephony Qualification

**Decision**: Design the eventual Linux containers for AKS, with Azure Container Registry,
managed identities, private Cosmos connectivity, Key Vault, and Azure Monitor. These are later
Terraform targets, not cloud resources required or provisioned for setup.

Call pods must transition `serving -> draining -> drained -> terminating`. Stop new admission,
retain existing media routing until calls finish, and only then allow rollout or scale-in.
If calls remain, postpone planned retirement. HPA/cluster autoscaler and deployment automation
must not independently delete active call pods. Grace periods and disruption budgets are secondary
controls, not a guarantee that arbitrary-length sockets survive termination.

Keep live telephony behind an adapter and disabled for this milestone. Do not adopt standalone
ACS PSTN as an unconditional long-term provider. Microsoft documents a September 30, 2028
transition and October 23, 2026 onboarding restrictions for retiring services; restrictions do
not automatically cover supported Teams-aligned scenarios. TPE documents outbound streaming
from calls but that alone does not prove audio can be injected back into a call. Qualification
of bidirectional audio, interruption, licensing, resource eligibility, geography, and SDK support
is an explicit gate before planning or enabling a live adapter. No non-Azure provider is approved.

**Rationale**: AKS permits explicit pre-drain orchestration. Uvicorn closes established WebSockets
on shutdown, so increasing a termination timer alone does not preserve calls. A provider-neutral
boundary prevents the scaffold from committing to a lifecycle-incompatible telephony product.

**Alternatives considered**: Container Apps simplifies operations, but its normal termination
behavior alone cannot establish the required call-aware drain. The documented 240-second HTTP
timeout is not evidence of a 240-second upgraded-WebSocket lifetime. Third-party telephony requires
the constitution's capability-gap assessment and maintainer approval before adoption.

Sources: [AKS autoscaler](https://learn.microsoft.com/en-us/azure/aks/cluster-autoscaler),
[Pod lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/),
[ACS lifecycle guide](https://learn.microsoft.com/en-us/azure/communication-services/acs-retirement-and-breaking-changes-guide).

## 7. Privacy and Observability

**Decision**: Keep audio, transcripts, request summaries, and tool payloads only in bounded volatile
session memory; purge on disconnect and enforce the five-minute terminal cleanup deadline.
Never write them to Cosmos, logs, traces, queues, dumps, or local spill files. Cosmos TTL is
only for metadata retention, not a promise of immediate physical content deletion.

Emit allowlisted JSON events with UTC timestamp, severity, service, environment, event name,
outcome, correlation ID, and trace ID where available. Build local capture tests for correlation,
redaction, and error classification. Later Azure Monitor alerts need thresholds, owners, linked
runbooks, and verified delivery; no alerting claim is satisfied by printing an exception.
Both services also emit application-owned metadata-only distributed traces with cross-service
context propagation and safe span attributes. Monitor management as well as runtime errors,
latency, dependency failures and saturation. Local tests use in-memory collectors without cloud
credentials; SDK tracing is a separate, disabled-by-default facility, not a substitute for this.

**Rationale**: TTL background deletion and backups make persistence of sensitive conversation
content incompatible with a simplistic five-minute deletion claim. Production residency,
disclosure, audit retention, and provider data handling remain required release approvals.

**Alternatives considered**: Durable conversation histories or raw payload logging are excluded.

Sources: [Cosmos TTL](https://learn.microsoft.com/en-us/azure/cosmos-db/time-to-live),
[Cosmos backups](https://learn.microsoft.com/en-us/azure/cosmos-db/online-backup-and-restore).

## 8. Verification and GitHub Actions

**Decision**: Native Windows Server 2022 and Ubuntu 24.04 CI on Python 3.12 runs locked installs,
Ruff, mypy, pytest, and Chromium shell smoke checks. Ubuntu-only jobs build and run both Docker
images. Credential-free starter suites cannot initialize Azure identity discovery, Cosmos,
telephony, or model SDK network calls; tests explicitly deny those destinations.

Use `pull_request` and protected-branch pushes, `contents: read`, full-SHA action pins, and no
publication, cloud credentials, or deployments in pull-request jobs. Pre-commit does fast local
static checks; CI repeats them and runs the automated tests. Dependency advisories and provider/
browser downloads are install/verification dependencies, not live application integrations.

**Rationale**: A green test-file collection is insufficient: assert health bodies, no-cloud startup,
WebSocket disconnect/limits, browser rendering, and deliberate CI failure on a broken assertion.

**Alternatives considered**: Linux-only tests miss Windows-specific failures. Docker job/service
containers do not establish native Windows support. Cloud credentials in PRs increase exposure.

Sources: [Playwright CI](https://playwright.dev/python/docs/ci),

## 9. OpenAI Agents SDK for Runtime Agent Management

**Decision**: Use the OpenAI Agents SDK for Python, distribution `openai-agents` with its `realtime`
extra, imported as `agents`. Backend `RealtimeAgent` definitions are materialized from validated,
pinned configuration projections; `RealtimeRunner` and `RealtimeSession` provide realtime agent
execution behind an application-owned adapter. Reflex/Cosmos continue to own agent configuration
CRUD. Do not substitute Azure AI Agent Service or invent a hosted agent-registry dependency.
Keep the SDK in the independent backend lock, with FastAPI/Pydantic compatibility tested before
acceptance; exact dependency resolution and runtime compatibility are not claimed by this research.

Use the documented Azure GA realtime URL
`wss://<resource>.openai.azure.com/openai/v1/realtime?model=<deployment-name>` through realtime
`model_config` URL/headers, with explicit approved authentication headers. Prefer managed-identity
bearer credentials for live use; recreate/renew connections with valid tokens as required.
Do not assume Chat Completions client support, a generic provider parameter, or a preview endpoint
proves realtime compatibility. Qualify the deployment, protocol, settings, and fresh-session latency.

Built-in realtime handoffs keep conversation history and do not provide the ordinary text
handoff's input filter. Therefore approved agent transitions create fresh realtime model sessions
using only allowed transfer fields, preserving the phone-facing FastAPI socket and the call's
pinned revision. Do not replay audio, transcripts, foreign prompts, or old tool results. The
trusted domain policy controls agent visibility, transition commitment, output epochs, and tool
authorization; SDK prompt instructions and handoff lists are not security controls.

By default, disable both tracing mechanisms before creating any agent session: global SDK tracing with
`OPENAI_AGENTS_DISABLE_TRACING=1` and `agents.set_tracing_disabled(True)`, and realtime tracing
with `RealtimeRunConfig` setting `tracing_disabled=True` and session model `tracing=None`.
Redact SDK model/tool debug logging too. Sensitive-data exclusion alone does not disable the
default exporter. Explicit application flags may enable SDK or realtime tracing only through
the privacy/destination controls in the interface contract. Apply process-wide settings at startup;
reject an opt-in whose content exclusion cannot be demonstrated with the selected provider.
Do not attach to already traced sessions or use durable SDK stores/resume histories. Exported
traces of any kind must exclude credentials, prompts, audio, transcripts and tool payloads.

Expose approved function-tool wrappers through the existing management capability gateway.
Do not directly attach arbitrary MCP servers to realtime agents: automatic discovery/filtering
does not enforce current per-action permissions or read-only/public classification. SDK support
for MCP does not authorize a gateway bypass. Local tests use the pinned SDK's documented
`ScriptedRealtimeModel` or an injected `RealtimeModel` double, tracing disabled, and denied live
egress; default startup constructs no live model connection or credential discovery chain.

**Rationale**: Satisfies the requested agent SDK while preserving dynamic configuration, the
community/context boundaries, immediate revocation ordering, privacy, and credential-free setup.

**Alternatives considered**: Handwritten model orchestration alone would not satisfy the SDK
requirement. Default realtime handoffs would expose prior history. An admin SDK dependency is
unnecessary until management actually executes agents; interactive testing there remains deferred.

Sources: [Realtime guide and Azure endpoints](https://openai.github.io/openai-agents-python/realtime/guide/),
[Realtime handoffs](https://github.com/openai/openai-agents-python/blob/v0.24.0/src/agents/realtime/handoffs.py),
[Tracing](https://openai.github.io/openai-agents-python/tracing/),
[SDK configuration](https://openai.github.io/openai-agents-python/config/),
[Testing](https://openai.github.io/openai-agents-python/testing/),
[MCP integration](https://openai.github.io/openai-agents-python/mcp/).

## Research Outcome

All technical choices needed for the credential-free foundation are resolved. Live telephony
qualification, model quotas, production privacy approval, and scale/load evidence are later
delivery gates, not assumed prerequisites or completed acceptance tests for this milestone.
Local story checkpoints use deterministic tests. Their live evidence remains pending until the
authorized-environment gate proves identity, networking, provider access and quota readiness.
The participant-based manager study is deferred; automated management tests remain in scope.
